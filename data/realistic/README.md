# CodeUtsav PS2 - held-out test dataset (realistic)
Synthetic, seeded (seed=2026), 2500 consumers x 540 days (2025-01-01 .. 2026-06-24). Generated by `make_test_dataset.py`.
**Never train on `labels.csv`-derived columns of this set; it is a test set.**

## Files
| file | role | description |
|---|---|---|
| readings.csv.gz | input | one row per consumer-day |
| consumers.csv | input | master data |
| transformer_energy.csv | input | energy delivered into each distribution transformer per day |
| labels.csv | evaluation only | ground-truth scenario / cause per consumer |
| true_kwh_wide.csv.gz | debug (optional) | what the consumer really used (consumers x dates) |

## readings.csv columns
- `recorded_kwh` - daily energy reported by the meter. **Empty = missing reading.**
- `voltage_v`, `current_a`, `power_factor` - daily-mean electrical measurements. Empty when the meter did not report.
  Implied energy = voltage_v * current_a * power_factor * 24 / 1000 (kWh). Theft/faults can make it disagree with `recorded_kwh`.
- `peak_share` - share of the day's energy used in the evening peak (load-shape signal).
- `tamper_flag` - cover-open / magnetic event reported by the meter (1 = event). Noisy: ~1% of honest meters also raise it.
- `fault_flag` - meter self-diagnostic code (1 = event). Also noisy.
- `heartbeat_ok` - 0 when the communication gateway missed its heartbeat.
Note: on a comm back-fill day the meter uploads the accumulated energy as one lump (current is derived from it).

## consumers.csv / transformer_energy.csv
category (residential/commercial/industrial), sanctioned_load_kw, tariff, transformer_id (~25 consumers each), feeder_id (8 transformers each),
meter_install_date (later than 2025-01-01 = new consumer with short history). Technical losses are ~4%, so
`input_kwh - sum(consumer true use)` ~ 4%; unrecorded (stolen/faulty) energy shows up as a larger gap.

## labels.csv
`cause` in Normal | Theft | MeterFault | CommFailure | LegitAbnormal; `scenario` is one of 22 sub-types; `event_start_*` is when the
anomaly began (blank for consumers with no discrete event).

| cause | scenarios |
|---|---|
| Normal | normal_regular, normal_new_consumer, normal_noisy_dupes |
| Theft | theft_step_drop, theft_gradual, theft_intermittent, theft_peak_bypass, theft_near_zero |
| MeterFault | fault_stuck, fault_zero, fault_spikes, fault_drift_low, fault_drift_high |
| CommFailure | comm_long_gap, comm_intermittent, comm_backfill_lump |
| LegitAbnormal | legit_vacation, legit_extended_absence, legit_guest_spike, legit_new_load_up, legit_solar_efficiency_down, legit_move_out |

All consumers also experience a shared seasonal curve, a weather AR process and a shared heatwave (days 430-445), none of which is an anomaly.

- F1: 0.907

- Recall: 0.859
- FPR: 0.003
- Precision_at_k: 0.922
- Macro_F1_5class: 0.961
Use these as a sanity bar: the simulator is cleaner than real data, so your model should land in the same region, not far below it.
Evaluate with PR-AUC / recall-at-fixed-FPR, not accuracy (theft is a minority class).
